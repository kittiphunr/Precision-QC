# ขั้นตอน Deploy ขึ้นโฮสต์จริง

คู่มือนี้สำหรับอัปโหลดเว็บ Precision QC ขึ้น shared hosting / Apache / Nginx (โดเมนที่ล็อกไว้ตอนนี้คือ `kittiphun.rut.mcupr.ac.th` ดู `hosting/deploy-domains.txt`)
เว็บเป็น static ทั้งหมด **ไม่ต้องติดตั้ง Python หรือฐานข้อมูลบนเซิร์ฟเวอร์** (PHP ต้องใช้เฉพาะถ้าเปิดระบบรับ log ในหัวข้อที่ 4)

## 0) สิ่งที่ต้องมี

| อะไร | ใช้ทำอะไร |
|---|---|
| ผู้ใช้ปลายทางต่ออินเทอร์เน็ตได้ | หน้าเว็บโหลด Pyodide และฟอนต์จาก CDN (jsDelivr, cdnjs, Google Fonts) |
| **HTTPS** บนโดเมน | กล้อง (webcam) และ Pyodide ใช้ได้เฉพาะ secure context |
| โปรแกรม FTP/SFTP หรือ File Manager (FileZilla, cPanel, DirectAdmin) | อัปโหลดไฟล์ |
| (เฉพาะตอน build เอง) Python 3.11+, Node.js/`npx` | สร้างโฟลเดอร์ `deploy/` ใหม่ ดูหัวข้อที่ 1 |
| (เฉพาะระบบรับ log) PHP 7.4+ บนโฮสต์ | `hosting/log-endpoint/log.php` |

## 1) เตรียมไฟล์ (เลือกวิธีเดียว)

**วิธี ก — ใช้โฟลเดอร์ `deploy/` ที่อยู่ใน repo เลย** (ง่ายที่สุด)
`deploy/` ถูกตรวจโดย CI ให้ตรงกับโค้ดล่าสุดเสมอ ดึงโค้ดล่าสุด (`git pull`) แล้วใช้ได้ทันที

**วิธี ข — build เอง** (เมื่อเปลี่ยนโดเมน หรือแก้โค้ดใน `web/`, `web-dashboard/`, `precision_qc/`)
```bash
pip install -r requirements.txt
python scripts/build_site.py --out deploy --lock-domain <โดเมนของคุณ>
```
- ใส่ `--lock-domain` ได้หลายโดเมน และบันทึกโดเมนไว้ใน `hosting/deploy-domains.txt` (CI ใช้ไฟล์นี้ตรวจว่า `deploy/` ตรงกับโค้ด)
- ต้องมี Node.js/`npx` เพราะ build คอมไพล์ CSS ของเวอร์ชัน Dashboard (Tailwind) และย่อ JavaScript (terser)
- ถ้าไม่ใส่ `--lock-domain` จะได้เว็บแบบไม่ล็อกโดเมน/ไม่ย่อโค้ด เหมาะกับทดสอบเท่านั้น **ไม่ควรอัปโหลดขึ้นโฮสต์จริง**

โครงสร้างผลลัพธ์:
```
deploy/
├─ index.html      หน้าแรกให้เลือกเวอร์ชัน
├─ pure/           เวอร์ชัน Pure.css       (เปิดที่ /pure/)
└─ dashboard/      เวอร์ชัน Dashboard      (เปิดที่ /dashboard/)
```
แต่ละโฟลเดอร์ย่อย self-contained อัปโหลดเฉพาะเวอร์ชันที่ต้องการเพียงอย่างเดียวก็ได้

## 2) อัปโหลด

1. ล็อกอิน FTP/SFTP หรือ File Manager ไปที่ `public_html/` (หรือโฟลเดอร์ย่อย เช่น `public_html/qc/`)
2. อัปโหลด **เนื้อใน** `deploy/` ทั้งหมด (ไม่ใช่ตัวโฟลเดอร์ `deploy` เอง) ให้ได้ `public_html/qc/index.html`, `public_html/qc/pure/…`, `public_html/qc/dashboard/…`
   - อยากให้ผู้ใช้เปิดเวอร์ชันเดียวตรง ๆ: อัปโหลดเนื้อใน `deploy/pure/` (หรือ `dashboard/`) ขึ้น `public_html/qc/` ได้เลย
3. **ต้องอัปโหลดไฟล์ซ่อน `.htaccess` ไปด้วย** (ในแต่ละโฟลเดอร์ `pure/`, `dashboard/`) — ใน FileZilla เปิด *Server → Force showing hidden files*
   ไฟล์นี้กันไม่ให้เซิร์ฟเวอร์รันไฟล์ `.py` เป็นสคริปต์, ตั้ง MIME ที่ถูกต้อง และตั้ง cache ให้หน้าเว็บ/`config.js` ตรวจเวอร์ชันใหม่ทุกครั้ง
4. ตรวจว่าโฟลเดอร์ `py/precision_qc/` และ `samples/` ขึ้นครบ (เว็บใช้ไฟล์ `.py` เหล่านี้เป็นข้อมูลที่ Pyodide โหลดไปรันในเบราว์เซอร์)

### ถ้าโฮสต์เป็น Nginx (ไม่อ่าน `.htaccess`)
เพิ่มในไฟล์ตั้งค่าเซิร์ฟเวอร์:
```nginx
location ~ \.py$ { default_type text/plain; }
location ~* \.(html|json)$ { add_header Cache-Control "no-cache"; }
location = /qc/pure/config.js      { add_header Cache-Control "no-cache"; }
location = /qc/dashboard/config.js { add_header Cache-Control "no-cache"; }
```
(ปรับ path `/qc/` ให้ตรงกับที่อัปโหลดจริง)

## 3) ตรวจหลังอัปโหลด

- [ ] เปิด `https://<โดเมน>/qc/` ได้ มีหน้าเลือกเวอร์ชัน → เข้า `pure/` และ `dashboard/` ได้
- [ ] สถานะมุมหน้าจอเปลี่ยนเป็น **"พร้อมใช้งาน"** (ครั้งแรกอาจใช้เวลาสักครู่ เพราะโหลด Pyodide)
- [ ] กดภาพตัวอย่างในหน้า **ตรวจจาน** และ **นับดอกเห็ด** (`caps.html`) แล้วเห็นผล ปุ่มรายงาน PDF ใช้งานได้
- [ ] (Dashboard) ปุ่มถ่ายจากกล้องเปิดได้ (ต้อง HTTPS และผู้ใช้กดอนุญาตกล้อง)
- [ ] ท้ายหน้ามีบรรทัด "บันทึกการใช้งานในเครื่องนี้ … รายการ (ไม่ส่งออกนอกเครื่อง)"
- [ ] ถ้าเปิดบนโดเมนอื่นที่ไม่ได้ล็อกไว้ เว็บต้องไม่ทำงาน (ระบบล็อกโดเมน)

### ปัญหาที่พบบ่อย
| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| ค้างที่ "กำลังเตรียมระบบ" หรือขึ้น "เตรียมระบบไม่สำเร็จ" | เครือข่ายเข้า CDN ไม่ได้ (หน่วยงานบล็อก jsDelivr?) หรือไม่ได้เปิดผ่าน HTTPS หรือไม่ได้ขึ้นไฟล์ใน `py/` / `manifest.json` |
| ไฟล์ `.py` โหลดไม่ได้ (error 403/500 ใน DevTools) หรือได้ผลลัพธ์แปลก ๆ | ลืมอัปโหลด `.htaccess` ทำให้บางโฮสต์พยายามรัน `.py` เป็นสคริปต์แทนที่จะส่งเป็นข้อความ |
| หน้าขึ้นข้อความ "โปรแกรมนี้ไม่ได้รับอนุญาตให้ใช้งานบนโดเมนนี้" | โดเมนไม่ตรงกับที่ล็อกไว้ตอน build → build ใหม่ด้วย `--lock-domain <โดเมนจริง>` |
| เห็นเวอร์ชันเก่าหลังอัปเดต | เบราว์เซอร์แคช: กด Ctrl+F5 ตรวจว่า `.htaccess` ขึ้นครบ (หน้าเว็บใช้ `?v=<hash>` กับไฟล์ JS/CSS อยู่แล้ว) |
| กล้องเปิดไม่ได้ | ไม่ใช่ HTTPS หรือผู้ใช้ปฏิเสธสิทธิ์กล้อง |

## 4) (ไม่บังคับ) เปิดระบบรับ log การใช้งาน — ระดับ B

ค่าเริ่มต้น **ปิด** (ข้อมูลอยู่ในเครื่องผู้ใช้อย่างเดียว) เปิดเมื่อพร้อมเท่านั้น รายละเอียดเต็มอยู่ใน [LOGGING.md](LOGGING.md)

1. **ตรวจนโยบาย PDPA** ของสถาบันก่อน (ระบบถามผู้ใช้ก่อนส่งทุกครั้ง และไม่ส่งภาพ/ชื่อไฟล์/IP)
2. อัปโหลดโฟลเดอร์ `hosting/log-endpoint/` (ไฟล์ `log.php`, `data/.htaccess`) ขึ้นเป็น `public_html/qc/log/`
   - โฟลเดอร์ `data/` ต้องให้ PHP เขียนได้ (ปกติ `755` ที่เจ้าของเป็น user ของเว็บ ถ้าเขียนไม่ได้ลอง `775`)
3. แก้ `config.js` **บนเซิร์ฟเวอร์** ในแต่ละเวอร์ชันที่ใช้ (`pure/config.js`, `dashboard/config.js`) เป็น path ตายตัวจาก root ของเว็บ เพื่อให้ใช้ได้ทั้งสองเวอร์ชัน:
   ```js
   window.PQC_CONFIG={logEndpoint:"/qc/log/log.php"};
   ```
4. **ตรวจว่าไฟล์ log เปิดจากเว็บไม่ได้**: `https://<โดเมน>/qc/log/data/` ต้องได้ **403** (บน Nginx ต้องเพิ่ม `location /qc/log/data/ { deny all; }` เอง เพราะไม่อ่าน `.htaccess`)
5. ทดสอบ: เปิดหน้าเว็บ → ต้องเห็นแบนเนอร์ขอความยินยอม → กด "ยินยอม" แล้ววิเคราะห์ภาพตัวอย่าง 1 ภาพ → ภายใน ~10 วินาทีต้องมีไฟล์ `data/usage-YYYYMMDD.jsonl` เกิดขึ้น
6. ดึงไฟล์ `data/usage-*.jsonl` ผ่าน SFTP มาวิเคราะห์ (ไฟล์เก่ากว่า 365 วันถูกลบอัตโนมัติ)

ปิดระบบ: ตั้ง `logEndpoint:""` กลับ แบนเนอร์และสวิตช์จะหายไปเอง

## 5) อัปเดตเวอร์ชันภายหลัง

1. `git pull` (หรือ build ใหม่ตามหัวข้อที่ 1 ถ้าเปลี่ยนโค้ด/โดเมน)
2. อัปโหลดทับไฟล์ในโฟลเดอร์ `pure/` และ `dashboard/`
3. ⚠️ **อย่าให้ `config.js` ถูกทับโดยไม่ตั้งใจ** — ไฟล์ใน `deploy/` มี `logEndpoint:""` ถ้าอัปโหลดทับ ระบบรับ log จะถูกปิด ให้ข้ามไฟล์ `config.js` ตอนอัปโหลด หรือแก้ซ้ำหลังอัปโหลด
4. ⚠️ **อย่าลบ/ทับโฟลเดอร์ `log/data/`** — เป็นที่เก็บ log ที่เก็บไว้แล้ว (อัปโหลด `log.php` ทับได้เมื่อมีการอัปเดตตัวรับ เช่นรอบที่เพิ่มเหตุการณ์ใหม่ ไม่เช่นนั้นเหตุการณ์ใหม่จะถูกตัดทิ้งฝั่งเซิร์ฟเวอร์)
5. ทำรายการตรวจในหัวข้อที่ 3 ซ้ำ

**ย้อนกลับ (rollback):** เก็บสำเนาโฟลเดอร์ `pure/` และ `dashboard/` เดิมไว้ก่อนอัปโหลดทับ (เช่นเปลี่ยนชื่อเป็น `pure.bak/`) ถ้ามีปัญหาให้เปลี่ยนชื่อกลับ

## 6) ทางเลือก: GitHub Pages

ถ้าไม่ได้ใช้โฮสต์ของตัวเอง ใช้ workflow *Deploy web app to GitHub Pages* (Settings → Pages → Source: **GitHub Actions** แล้วกด *Run workflow*) เว็บจะอยู่ที่ `https://<username>.github.io/<repo>/` — ระบบรับ log (ระดับ B) ใช้ไม่ได้บน GitHub Pages เพราะไม่มี PHP
